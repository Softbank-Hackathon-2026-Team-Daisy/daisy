# PR #19 피드백 반영

기준: 2026-10-01. 엔티티·공통 기반 PR에서 승인된 수정 범위이며 실행 서비스는 별도 브랜치 작업입니다.

- 원인: DaisyException의 details 경로가 없고 낙관적 잠금 예외가 공통 500으로 응답했습니다. 생성자·handler로 안전한 명시 값의 전달을 연결하고 낙관적 잠금을 STATE_CONFLICT 409로 처리했습니다. 원인 미판별 DB 무결성 예외는 INTERNAL을 유지하며 constraint별 변환은 소유 서비스 책임입니다.
- 검증: 실제 application.yml을 읽는 Jackson 슬라이스에서 snake_case·UTC Instant, details 방어 복사·HTTP 전달, 낙관적 잠금/미분류 무결성 구분을 검사했습니다. 기존 비밀값 비노출·요청 ID·매핑 검사를 포함한 13개 테스트와 Spotless·build가 통과했습니다.
- 명세: Jenkins 소유·폴링·plan/apply 분리, source_version_id 선택, map→API digest projection, attempt 0/재사용/호출 실패 구분, SSE 필터·운영 락 해제 방향, 선택 필드 분류와 migration 대조 목록을 갱신했습니다.
- 실제 main 대조: cd-plan/cd-apply Job과 tf-run.sh를 확인했습니다. plan summary는 문자열·AI 사용량 합계이며 대상 결과는 로그뿐입니다. request_id 검색·부분 대상 apply·구조화된 원본·state backend 목표를 이미 구현된 기능으로 표현하지 않았습니다.
- 미결: 다중 대상 승인/단일 approval_id·프로젝트명 confirm_text, MSA digest 대표 정책·attempt 0 API 표시·step DTO, 호출별 사용량·plan 기한/input hash·request_id 검색 및 중복 방지, 실제 backend 정규화입니다.
- 후속: 은현의 V1 별도 PR 도착 후 실제 PostgreSQL 제약·저장조회·경합·기동을 대조합니다. 이번 작업은 entity/DDL·Security·SSE 구현·실제 Jenkins 제출을 추가하지 않았습니다.

검증 명령(Java 21, 기존 GRADLE_USER_HOME):

```bash
./gradlew spotlessApply test --no-daemon --offline
./gradlew check build --no-daemon --offline
```

# 9/30 작업 일지 — DB 설계로 범위 조정

## 작업 범위

- 백엔드가 DB 초안을 먼저 작성하고, 하은현의 PR 검토로 보완하는 방식으로 진행해요.
- 이번 작업은 [DB 설계안](../database-design.md)과 역할 문서만 다뤄요. 마이그레이션·엔티티·서비스·컨트롤러는 작성하지 않아요.
- 앞서 착수했던 미커밋 Java 파일 10개와 보안 의존성·구현 착수 명세 변경은 사용자 요청으로 제거했어요. 기존 개발 환경과 커밋된 업무 문서는 보존했어요.
- 인증·인가는 하은현 담당으로 분담안을 수정했어요. 김승환은 실행 규칙·승인 유효성·Jenkins 연동·멱등성·복구와 이벤트 기반에 집중해요.

## 설계 원칙

- 확정된 API 상태값과 데이터 의미를 유지하고, 새 내부 이름·관계는 백엔드 설계 제안으로 표시해요.
- 테이블 수만큼 도메인 서비스·Repository 인터페이스를 미리 만들지 않아요. 변경 책임과 트랜잭션 경계로 DDD를 적용해요.
- 실제 인프라 실행 주체는 Jenkins예요. 백엔드는 명령·승인·결과를 연결하며 Terraform 실행부나 Claude 호출을 다시 만들지 않아요.
- 인프라팀 의견이 필요한 항목도 백엔드의 권장안을 먼저 적어 리뷰를 요청해요. 전체 설계를 미결 상태로 남기지 않아요.

## 검증 범위

- 문서의 관계·제약과 기존 PR 요구사항을 대조해요. DB를 만들거나 DDL을 실행한 결과는 아니에요.
- Astra 설계 후 6.1 Sol로 교차검토했고, STOP과 APPLY의 상태 소유권·동일 커밋 재빌드 연결·불변 자격증명 참조 조건을 보완했어요.
- ERD 3개·테이블 17개의 선언/관계 참조와 문서 상대 링크를 정적으로 확인했어요. Mermaid 렌더링·DB 제약 실행 검증은 아직 하지 않았어요.
- 기능 코드를 제거했으므로 이 작업에서 애플리케이션 빌드·기능 테스트 결과를 주장하지 않아요.
- 구현 준비 중 시작한 임시 PostgreSQL 프로세스는 종료했고 데이터는 삭제하지 않았어요.

## 후속 순서

1. DB 설계 PR에서 은현에게 계정·권한·관리 테이블과 실행 도메인 연결을 검토받아요.
2. 인프라팀에는 실행 식별자·승인된 plan·상태/사용량 전달·state 충돌 경계를 확인받아요.
3. 후속 파일 생성은 엔티티·값 객체·상태 타입·매핑 검증 범위로 구분하고, 비즈니스 기능 구현과 한 번에 섞지 않아요.

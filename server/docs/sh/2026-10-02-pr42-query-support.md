# #42 실행 API 연결을 위한 조회 보완

## 변경

- `DeploymentQueryService.projectIdOf(actorId, deploymentId)`를 추가했어요. 소속 프로젝트를 찾은 뒤 조회 권한을 확인하고 반환해요. 명령 서비스의 변경 권한 검사는 그대로 유지해요.
- `currentByTarget(actorId, projectId, pointers)`를 추가했어요. 모든 요청 대상에 `CurrentResult(status, deployment)`를 반환해요. NULL 포인터는 `none`, 확인된 성공 참조는 `confirmed`, 확인 실패는 `unverified`예요.
- 권한 오류와 DB 장애를 대상 실패로 숨기지 않아요. 잘못된 포인터·실패 상태·종료 시각 없음·이미지 JSON 구조 문제만 해당 대상의 결과로 내려요.
- 기존 `current()`는 #42의 기존 코드를 바로 깨지 않도록 유지해요. 두 메서드는 SQL·검증 로직을 공유하고 새 의존성·계층은 추가하지 않았어요.
- `ExecutionInputs.recordBuild` 주석을 선택한 기존 성공 빌드 확인으로 수정했어요. 새 빌드 등록은 별도 연결이에요.
- SPEC·내부 연결 계약·server 결정 기록을 갱신했어요. DB/V1·은현님 소유 코드·공개 경로는 바꾸지 않았어요.

## 은현님 연결 지점

1. 배포 ID만 있는 경로는 인증된 actor와 `projectIdOf`를 호출한 뒤 기존 명령/SSE 서비스로 넘겨요.
2. A-02는 `currentByTarget`으로 전환하고 404/409를 잡아 대상별로 재호출하는 fallback을 제거해요. `status` → `current_status`, `deployment` → 공개 current DTO로 매핑해요.
3. 대상 확인 실패가 예외가 아니므로 목록 조회와 같은 읽기 트랜잭션으로 연결할 수 있어요. #42의 실제 컨트롤러 변경·권한 철회·응답 검증은 연결 후 다시 확인해요.

## 검증

- Java 21, Gradle 8.14 캐시, 독립 로컬 PostgreSQL 17 사용. 테스트별 임시 스키마를 만들고 테스트 종료 시 제거해요.
- `./gradlew spotlessApply check build --rerun-tasks --no-daemon --offline` 성공.
- 총 **134개 테스트 통과**, 실패·오류·스킵 0개. 이 중 실제 PostgreSQL 통합 테스트 **19개**예요.
- 같은 읽기 트랜잭션 안에서 정상·NULL·없는·다른 대상·실패·미종료·이미지 오류 포인터가 섞인 조회 및 커밋 성공을 확인했어요. 다른 프로젝트 포인터도 확인 실패로 격리해요.
- 접근 정책의 401/403/404 그대로 전파, 정책 누락 거절, DB 장애 전파, 권한 철회 후 프로젝트 ID 반환 거절을 확인했어요. 기존 current·deployed_to 회귀 테스트도 통과했어요.
- 테스트의 입력·접근 어댑터는 테스트 대역이에요. **#42 전체 통합, 실제 Jenkins 실행, HTTPS/프록시 경유 SSE 실연동 검증을 대신하지 않아요.**

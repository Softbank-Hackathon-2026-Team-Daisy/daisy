# 10월 1일 공통 오류 처리와 요청 추적

## 작업 범위

- 사용자가 오류 코드 목록에 더해 공통 예외, 오류 응답과 전역 처리기, 요청 ID 추적을 승인했어요.
- `common/error`와 `common/web`에 두며 인증·인가·업무 API·SSE·Jenkins·DB 마이그레이션은 추가하지 않아요.
- 403 `FORBIDDEN`, 422 `MANIFEST_INVALID`는 사용자 위임으로 정한 이름이에요. 웹·앱에 이미 공유됐다고 취급하지 않아요.
- 구현은 6.1 Sol, 검토는 별도 6.1 Sol이 담당해요. 원래 요청한 계약 문서 최신화도 별도로 진행해요.

## 설계 이유

- 오류 응답은 기존 `{ error: { code, message, details, retryable } }`를 유지해요. 성공 응답을 새 봉투로 감싸지 않아요.
- Spring MVC의 기본 예외 처리 흐름을 활용해 404·405·415 등의 상태와 표준 헤더를 유지해요. 모르는 서버 오류만 안전한 내부 오류로 표현해요.
- 예외 원문·SQL·비밀값·거절된 입력값을 오류 응답과 공통 오류 로그에 복사하지 않아요. 필드 검증 안내도 고정된 안전한 문구를 사용해요.
- 요청 ID는 추적용이에요. 인증 토큰, 배포 ID, 멱등성 키, Jenkins 명령의 request_id와 구분해요. 유효한 단일 헤더를 사용하거나 UUID를 새로 만들어요.
- 로그 MDC의 request_id를 요청 처리 동안 설정하고 finally에서 이전 값으로 복원해요. JSON 로그는 기존 Spring Boot 기능을 사용해요.
- 범용 기반 엔티티·유틸·별도 로깅 의존성을 추가하지 않아요.

## 인계와 제한

- 인증 필터에서 발생하는 오류는 MVC 예외 처리기 밖이에요. 은현의 인증 진입점·접근 거부 처리기에 오류 응답 계약을 연결해야 해요.
- CORS 허용/노출 헤더, 프록시 스트리밍, SSE 생산 스레드나 임의 executor로의 추적 정보 전파는 이번 구현 범위가 아니에요.
- 엔티티는 있지만 Flyway 마이그레이션이 없으므로 빈 DB에서 서버 기동은 여전히 불가해요. 이번 검증은 DB 없이 공통 웹 계층과 필터를 검사해요.
- 원격 push·PR·Notion 원본 편집은 수행하지 않아요.

## 검증 결과

- `spotlessApply check build --no-daemon --offline` 성공. 공통 웹 테스트 5개·필터 테스트 3개·엔티티 테스트 3개, 총 11개를 통과했어요.
- 별도 리뷰에서 미전송 SSE 오류 누락과 비JSON Accept의 오류 응답 작성 문제를 찾아 수정하고 회귀 테스트를 추가했어요.
- JSON 로그 테스트 최초 실행은 독립 테스트 환경에 Spring Environment가 없어 실패했어요. 테스트 전용 LoggerContext에 MockEnvironment를 넣고, MDC 값을 로그 발생 시점에 캡처한 뒤 재검증했어요. 실제 앱 설정을 우회하거나 테스트를 삭제하지 않았어요.
- 공통 오류 응답·로그에서 예외 원문·SQL·거절값이 노출되지 않는지 검증했어요. 프레임워크·웹서버·프록시 모든 로그를 감사한 결과는 아니에요.
- 필드 오류는 전역 snake_case를 적용한 루트 필드만 반환해요. 개별 별칭이나 배열/map 세부 경로는 후속 계약이 필요해요.
- 계약 최신화본은 기존 외부 메모 폴더의 `backend-api-contract-2026-10-01.md`에 저장했어요. Jenkins 실행 책임·상태 구분·승인/재사용·오류 코드를 갱신하되 합의·백엔드 선택·미결을 구분했어요. Notion 원본이나 GitHub 댓글을 수정한 것은 아니에요.

# 9/30 작업 일지 — ERD 기반 엔티티 초안

## 범위

- DB 설계만 마친 뒤, 사용자 추가 승인으로 기본 17개 테이블의 JPA 엔티티를 작성해요.
- 코드는 6.1 Sol이 작성하고 별도 6.1 Sol이 ERD 대조 리뷰를 해요. 기존에 중단했던 서비스·Jenkins 클라이언트 코드를 복원하지 않아요.
- [DB 설계안](../database-design.md)의 컬럼·NULL·타입·키를 기능별 `domain` 패키지로 옮겨요. 계정·프로젝트 관리 영역은 은현 검토용 초안이며 인증·인가를 대신 구현하지 않아요.

## 선택과 경계

- 다른 도메인은 ID로 참조해요. 모든 FK를 객체 연관관계로 연결하거나 양방향 관계·cascade를 만들지 않아요.
- 복합 기본키 2개와 확정된 배포/대상 상태 타입 2개만 별도 타입으로 둬요. 은현 소유 역할과 아직 제안 단계인 상태값은 임의로 enum 확정하지 않아요.
- JSONB는 기존 Jackson/Hibernate, 시각은 Instant, 비용은 BigDecimal을 사용해요. 미확인 비용·토큰은 NULL을 유지해요.
- 이번 엔티티는 영속성 구조 초안이에요. 생성 메서드·조회 메서드·상태 전이·Repository·서비스·API는 실제 사용 사례 구현 때 추가해요. 범용 setter나 불필요한 계층은 만들지 않아요.
- 일반 UNIQUE는 매핑에 표현하지만 FK·CHECK·부분 UNIQUE·DB 기본값·운영 인덱스는 후속 Flyway에서 구현해요. JPA 매핑만으로 실행 안전성과 DB 무결성이 완성된 것은 아니에요.

## 검증과 인계

- `spotlessApply check build --no-daemon` 성공. DB 없는 Hibernate 메타데이터·복합키·상태 변환 테스트 3개를 통과했어요. 17개 엔티티, 252개 컬럼의 구조를 검증했어요.
- 별도 6.1 Sol 리뷰에서도 사전과 매핑의 불일치를 발견하지 않았어요. PostgreSQL 저장/조회·실제 제약·낙관적 잠금 경쟁을 검증한 것은 아니에요.
- 첫 오프라인 빌드는 기존 JUnit 전이 의존성 `apiguardian-api`가 캐시에 없어 중단됐어요. 기존 의존성을 내려받아 재실행했고, build 파일이나 의존성 목록은 바꾸지 않았어요.
- `ddl-auto=validate`를 유지해요. 마이그레이션 없는 빈 DB에서는 기동이 실패하므로, main 머지 전 Flyway와 실제 PostgreSQL 검증이 필요해요.
- Jenkins·Claude·Terraform·클라우드 호출은 하지 않아요. PR 게시·원격 push는 이번 범위에 포함하지 않아요.

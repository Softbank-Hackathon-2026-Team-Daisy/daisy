# 하은현 역할 — 인증·인가·관리·조회 API

기준: 2026-10-01. 현재 Jenkins 분담과 #19·#17 피드백 반영. 구현 완료 여부는 별도 명세·검증 기록을 따릅니다.

인증·인가를 독립 기능으로 책임지고, 프로젝트·저장소·대상 관리와 조회 기능을 완성합니다. 김승환의 실행 서비스·SSE 기반을 웹·앱 API에 연결합니다. 아래는 구현 완료를 뜻하지 않습니다.

[전체 업무](../work.md) · [김승환 역할](../sh/roles.md)

## 1. 담당 업무

| 영역 | 구현할 내용 | 핵심 확인 기준 |
|---|---|---|
| 인증·인가 | 로그인, Bearer 토큰 발급·검증, 계정·역할, 프로젝트 접근 정책·공통 인가 서비스 | 미인증 차단, viewer 변경/승인 차단, 다른 프로젝트 접근 차단 |
| 프로젝트·저장소 | 프로젝트 생성·목록·상세, 레포·브랜치 연결, manifest 존재·기본 입력 확인 | 잘못된 입력과 권한 없는 프로젝트 접근을 거절함 |
| 대상·버전 관리 | 대상 설정·자격증명 참조, 대상 상태, 선택 가능한 커밋·빌드 목록 | 다른 프로젝트의 대상·빌드가 섞이지 않음 |
| 배포 이력 조회 | 배포 목록·상세·상태 필터·페이지네이션, 대상별 결과·접속 URL | 부분 실패와 미완료 상태가 올바르게 표시됨 |
| plan·산출물 조회 | plan 요약, 생성 코드·스크립트 목록, 재사용·버전 정보 | 접근 권한·비밀값·만료된 참조를 처리함 |
| 사용량 조회 | 호출 내역, 배포·프로젝트 합산, 합의한 USD→KRW 변환·응답 | 미확인 비용을 0으로 바꾸지 않고 환율·반올림 기준을 지킴 |
| 사용자 요청 API | 배포·승인·거절·취소·재시도·롤백 요청을 실행 서비스에 연결 | 상태를 직접 변경하거나 Jenkins를 별도로 호출하지 않음 |
| 사용자 전달·계약 | 로그 조회, 공통 SSE 기반을 사용하는 엔드포인트, 인증 구조 적용, OpenAPI·테스트 | 권한·응답 형식·재연결 요청을 공통 계약대로 처리함 |

컨트롤러만 만드는 분담이 아닙니다. 담당 기능의 DTO·입력 검증·서비스·소유 데이터 저장 및 조회·OpenAPI·테스트까지 기능 단위로 완성합니다.

## 2. 김승환에게 받아서 사용할 것

- 배포·승인·취소·재시도·롤백을 요청할 실행 서비스와 샘플 응답.
- 실행 요청에 필요한 사용자·프로젝트·대상·커밋·plan 식별 정보.
- 상태·충돌·권한·입력 오류의 정의와 응답 매핑 기준.
- 인프라에서 수집·정리된 plan·로그·산출물·AI 호출 기록의 의미.
- 실행 공통 예외·SSE 연결·재생 구조와 호출 예제.

김승환에게 인증된 사용자 식별·프로젝트 조회/변경/승인 권한 검사 서비스를 제공합니다. 사용자 입력으로 전달한 역할을 신뢰하지 않습니다. Jenkins 폴링의 서비스 인증 정책도 김승환의 연동 요구와 맞추되, 사용자 로그인 토큰과 서비스 간 자격증명은 구분합니다.

김승환에게는 화면별 필수 응답, 입력·페이지네이션 조건, 조회 중 필요한 데이터 누락을 전달합니다. 기능·필드를 임의로 늘리지 않고 전체 업무 문서의 필수·선택 구분을 유지합니다.

## 3. 실행 서비스와 API의 경계

승인 요청의 예:

1. 하은현이 구현한 인증·인가 구조로 사용자·프로젝트 접근과 요청 형식을 확인합니다.
2. 검증된 사용자·요청을 김승환이 담당하는 실행 서비스로 전달합니다.
3. 실행 서비스가 현재 상태·plan 유효성을 확인하고 승인 기록·상태 변경·실행 연결을 처리합니다.
4. API는 실행 서비스의 결과·오류를 합의한 사용자 응답으로 변환합니다.

실행 서비스에서도 필요한 인가·대상 연결 검증을 수행합니다. 인증·권한 확인을 단순 UI 처리로 대체하지 않습니다.

## 4. 직접 맡지 않는 것과 경계

- 배포 상태 전이·승인 유효성·동시성·복구 정책을 API 안에 중복 구현하지 않습니다.
- Jenkins를 직접 호출하거나 배포 상태·승인 기록을 별도로 수정하지 않습니다.
- SSE 재생·연결 수명 관리와 보안 기반을 독립적으로 다시 만들지 않고 제공된 구조를 사용합니다.
- AI 원본 호출 기록의 수신·중복 방지는 김승환과 연결합니다. 조회 과정에서 호출 기록을 임의 생성하지 않습니다.
- Claude·Terraform·이미지 빌드·실제 배포는 인프라팀 담당입니다.
- 다른 담당 영역의 Repository·Entity를 직접 사용하지 않고 조회·실행 서비스 계약으로 연결합니다.
- 원본 산출물 보관과 서비스 조회의 경계, 빌드 수신 데이터의 저장 서비스는 함께 맞춥니다.

기존 작성한 코드·DDL은 먼저 공유하고 활용 방법을 맞춥니다. 역할 변경만으로 기존 작업을 폐기하거나 덮어쓰지 않습니다. 각자 소유 테이블과 Flyway 버전 번호는 사전에 조율합니다.

## 5. 첫 개발 순서

1. 현재 구현·DDL 진행 상황을 공유하고, 관리·조회 기능과 실행 서비스 호출 경계를 확인합니다.
2. 인증·인가 서비스와 테스트를 먼저 제공하고 프로젝트·대상·버전 관리 API에 적용합니다.
3. 합의한 DTO와 샘플 응답으로 배포·plan·산출물·사용량 조회를 연결합니다. 실제 결과 수집 완료까지 기다릴 필요는 없습니다.
4. 사용자 요청 API와 로그·SSE를 실제 실행 서비스에 붙이고 웹·앱과 함께 검증합니다.

테스트 대역이나 샘플 응답은 목업임을 표시합니다. 실제 응답에 없는 값을 만들어 제공하지 않습니다.

## 6. 완료 판단과 검증 근거

- 담당 API의 입력·응답·오류가 OpenAPI와 일치합니다.
- 다른 프로젝트의 배포·산출물·로그·사용량에 접근할 수 없습니다.
- 필터·페이지네이션·빈 결과·아직 도착하지 않은 결과를 처리합니다.
- 사용량 미확인과 실제 0을 구분하고 합산·환산 규칙을 검증합니다.
- 승인·재시도 같은 요청은 실행 서비스로 전달하며 핵심 상태 규칙을 우회하지 않습니다.
- 로그·SSE는 공통 보안·재연결 규칙을 따르고 웹·앱 연결 결과를 기록합니다.

# 작업 로그 (web)

`web/` 작업을 날짜별로 남겨요. 제출용 설계 문서와 심사 Q&A("어떤 과정으로 결정했나요?")의 근거로 써요.

## 규칙

- **하루 한 파일**, 이름은 `YYYY-MM-DD.md` (KST 기준)
- 스텝을 커밋할 때 로그도 **같은 커밋에** 갱신해요. 로그만 따로 커밋하지 않아요
- 커밋 해시 · PR · 이슈 번호를 남겨서 GitHub 기록과 이어요
- 결정은 여기와 `web/AGENTS.md` §10 결정 기록 **둘 다**에 적어요. 결정 기록은 에이전트가 읽는 규칙, 작업 로그는 사람이 읽는 과정이에요
- 막혔다 풀린 것은 "증상 → 원인 → 해결"로 적어요
- 비밀값 · 토큰 · 자격증명은 적지 않아요
- 한국어 해요체

## 템플릿

```markdown
# YYYY-MM-DD (Dn)

## 한 일
- 무엇을 했는지 — `커밋 해시`, PR #번호

## 결정 (확정)
- 결정 — 이유 (단계, AGENTS.md §10에도 기록)

## 결정 필요 (가칭)
- 항목 — 누가 정하나, 이슈 · 코멘트 링크

## 검증
- 실행한 명령과 실제 결과

## 막혔던 것
- 증상 → 원인 → 해결

## 다음에 할 일
-
```
